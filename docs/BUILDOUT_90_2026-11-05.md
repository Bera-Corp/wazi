current buildout dependency. This does not mark an independent review complete,
remove the owner approval flow, or allow unsigned packages to execute.

## Implemented additions

- community.handoff verifies a signed portable package and exact platform
  coverage, resolves an already enabled private instance, and requests an
  unapproved proposal. It checks the returned tenant, host, manifest, procedure,
  operation and project. It cannot issue approvals or deploy.
- scripts/platform_lifecycle.py prepares Linux Engine, Windows/WSL2 and macOS
  Desktop rollout bindings against exact signed environment coverage and the
  actual release/procedure for every forward/recovery job. A Linux guest result
  cannot qualify a desktop. Preparation does not execute anything.
- The package proposal API and signed package procedures support the existing
  health-check operation with only manifest verification and health checks.
  Mutating jobs retain their required owner approvals. Existing manifests and
  lifecycle procedure versions are preserved.
- scripts/lifecycle_service.py schedules the existing durable coordinator with
  bounded ticks and restart-safe SQLite state. Optional observeAfterSeconds on
  forward health actions delays submission and rejects cached health results
  older than the observation window. No new approval or credential renewal is
  performed by the scheduler.
- Phase 5 now has a private cohort/reliability ledger, explicit retry attribution,
  real terminal-receipt import, support transitions, consent-controlled feedback
  file export, offline reports and an authenticated workbench progress view.
  See PHASE5_ALPHA_OPERATIONS.md for commands and metric definitions.
- Qualified VPS deployment updates the protected Python context worker path
  alongside Go binaries, preserving prior configuration for rollback.

## Remaining source work and acceptance

Phase 2: finish expanded Immich/multi-service runtime integration and remaining
beneficiary/provider integration details. Live model calls and spending remain
owner-authorized setup, not assumptions made by code.

Phase 3: broader new-application profiles, richer catalog/workbench integration
and the complete hands-on contribution-to-install journey remain. The independent
review step is deferred for now; owner review and signed promotion remain.

Phase 4: PostgreSQL/MySQL engine-major conversion adapters and deep desktop
runtime enforcement integration remain incomplete. Only explicitly configured
Uptime startup migrations are supported; unsupported conversions stay blocked.
Portable preparation is available for the three families; actual desktop
qualification and Mac execution require the corresponding machines and evidence.
Cross-version canary/downgrade exercises, supply-chain evidence closure and wider
recovery coverage remain acceptance work.

Phase 5: expand to the 5–10 app alpha, collect actual local and VPS observations,
finish support/product polish and close the measured thresholds. No threshold
has been declared satisfied merely because this tooling exists. User testing,
OAuth configuration and the final demonstrated video remain later steps.
